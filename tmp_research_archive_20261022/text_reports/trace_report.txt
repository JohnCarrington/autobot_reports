11. MISSING PIECE: WHY 60-SECOND BACKOFF?
================================================================================

The observed 60-second 403 cadence is UNEXPLAINED by the code.

Possible root causes (ranked by likelihood):

1. [MOST LIKELY] The min_poll_interval_s = 300 gate is being bypassed
   by a second call path not traced in static analysis.
   The fetcher is being invoked every ~60 seconds despite the gate.
   Backoff IS set correctly (prevents 2h silence),
   but then 60s cadence fetcher invocation re-triggers 403.

2. The backoff_expiration calculation is wrong.
   mono + allowance_backoff_s should compute to 7200s offset,
   but calculated offset is effectively 60s (possible mono wraparound
   or arithmetic overflow in rare systems, unlikely on Linux).

3. Multiple IGPricesFeed instances are being created,
   each with fresh _quota_resumes_at_monotonic = 0.0,
   bypassing the shared backoff state.
   Static analysis shows only one instance, but runtime might differ.

4. A race condition in the main loop or exception handler is calling
   fetch_recent_m5 directly, bypassing IGPricesFeed.poll() entirely.
   fetch_recent_m5 itself logs the 403 and doesn't apply any backoff,
   so repeated calls hit 403 immediately.

SUMMARY
================================================================================

ROOT CAUSE (Confirmed):
  Main loop calls ig_feed.poll() every 2 seconds because archive_tail.poll()
  returns [] between M5 candle closes, triggering the else branch at
  main.py:315 even though the archive is fresh (not stale).

60-SECOND CADENCE (Unresolved):
  The backoff mechanism at market_data.py:244 is correctly triggered on 403,
  setting _quota_resumes_at_monotonic = mono + 7200.
  
  However, observed 403s occur every 60 seconds, not every 7200 seconds.
  
  This suggests either:
  - min_poll_interval_s gate is bypassed (untraced code path)
  - Backoff state is not persisted between calls
  - External mechanism calling fetcher every 60 seconds
  - Logic error in backoff calculation

NO PROPOSED FIX: Code tracing complete. Analysis shows both the documented
backoff mechanism AND the condition triggering repeated IG calls, but the
60-second interval cannot be fully explained from static code analysis alone.
