5. DIRECTIONAL SEMANTICS MAPPING
   ────────────────────────────────
   
   Established in code and validated empirically:
   
   IF first observation close_side = 'above' (approach from above):
      → through-level direction = SELL (downward acceptance to opposite side)
      → away/rejection direction = BUY (bounce upward, stay on approach side)
      → ACCEPT means acceptance_side = 'below' (opposite)
   
   IF first observation close_side = 'below' (approach from below):
      → through-level direction = BUY (upward acceptance)
      → away/rejection direction = SELL (bounce downward, stay on approach side)
      → ACCEPT means acceptance_side = 'above' (opposite)
   
   This mapping is HARDCODED in lines 167, 188 and validated universally across 1,016 ACCEPT cases.

   approach_side depends ONLY on: symbol, level_price, initial bar_close.
   It is set once and never mutated.

==== VERDICT ====

The accepted structural interaction engine DOES establish a causal approach_side
(encoded as first observation close_side) at interaction OPEN, independent of
all downstream outcomes. This is the foundational semantic for defining which
direction = "through" vs "away" at that level.

The mapping (approach from above → SELL through; approach from below → BUY through)
is universal and hardcoded in the acceptance logic. It holds perfectly across all
3,799 interactions in the dataset.
