CONFLUENCE-MAP CONSTRUCTION PIPELINE: POINT-IN-TIME RECONSTRUCTION RECIPE
==========================================================================

EXECUTIVE SUMMARY
─────────────────

The production codebase constructs a pre-session confluence-level map via a five-stage
pipeline: (1) assembling raw candidate levels from D1 pivots, PDH/PDL, H1/H4 swings,
round numbers, and BB bands; (2) clustering raw levels within a 5-pip tolerance window;
(3) assigning confluence scores (distinct category count); (4) ranking by confidence
and separation; and (5) emitting the final "key_levels" / "major_levels" / "zones"
map consumed by the live trading engine and briefing strategies.

The entry point is "morning_briefing.py" (the Anthropic-API-driven pre-session build),
with supporting deterministic foundation modules: "view_builder.py" (VIEW cache),
"significant_locations.py" (Stage 5 unified level snapshot), and "level_computation.py"
(Phase 7 deterministic ranking). For live trading, "view_builder.build_view()" is the
primary gateway; for historical backtest reconstruction, both "view_builder.build_view()"
and "significant_locations.build_significant_locations()" are callable with a target_iso
date and Stage-0b bar archives.

2. SIGNIFICANT-LEVEL BUILDERS (RAW LEVEL SOURCES)
──────────────────────────────────────────────────

A. CLASSICAL DAILY PIVOTS (P, R1–R3, S1–S3)
   ──────────────────────────────────────────
   SOURCE: ig_daily_pivots.py (IG REST, once-per-day; 2026-10-02 feature, build 2)
           OR daily_snapshot.py (cache-resident, deterministic rebuild from HTF D1 cache)
   
   FORMULA: view_builder.py:246–265 / ig_daily_pivots.py:141–150 / daily_snapshot.py:126–138
   P = (H + L + C) / 3
   R1 = 2*P - L,  S1 = 2*P - H
   R2 = P + (H - L),  S2 = P - (H - L)
   R3 = H + 2*(P - L),  S3 = L - 2*(H - P)
   
   EMITS (view_builder.py line 256–264 for each: P, R1, R2, R3, S1, S2, S3):
   Level(price=float, type=f"pivot_{name}", source="ig_daily_pivots")
   
   LIVE CACHE: /opt/tradingbot/cache/htf/daily_pivots.json
   (Read by: view_builder.py:246–265 via ig_daily_pivots.read_pivots)
   (Populated by: ig_daily_pivots.run_daily_fetch, scheduled at SCHEDULED_HOUR_UTC:MM UTC, default 03:00)

B. PREVIOUS-DAY HIGH/LOW (PDH, PDL)
   ──────────────────────────────────
   SOURCE: D1 bar immediately prior to today (skips Sunday; Mondays use Friday)
   SELECTOR AUTHORITY: htf_cache.select_prior_completed_d1(pair, trading_date)
   
   RETRIEVAL (view_builder.py:283–297):
   bar = _pick_pdh_pdl_bar(now_utc, d1_candles) [weekday logic at :209–226]
   
   EMITS:
   [Level(pdh, "pdh", f"d1_bar:{date_str}"), Level(pdl, "pdl", f"d1_bar:{date_str}")]
   
   FALLBACK ON MISS: returns ([], "pdh_pdl_bar_missing")

C. 2-WEEK S/R HIGHS/LOWS (2W_HIGH, 2W_LOW)
   ──────────────────────────────────────
   DEFINITION: The 10 most recent D1 bars strictly before today
   
   RETRIEVAL (view_builder.py:300–317):
   bars = _recent_d1_bars(now_utc, TWO_WEEK_TRADING_DAYS=10, candles=d1_candles)
   → emits Level(high, "2w_high", f"d1_bar:{date}") and Level(low, "2w_low", ...) for each bar

D. ROUND NUMBERS (ROUND_00, ROUND_50)
   ──────────────────────────────────
   GRID: ±150 pips around current price (ROUND_RANGE_PIPS)
   STEP: 50-pip boundaries (1.3500, 1.3550, 1.3600, ...)
   
   CONSTRUCTION (view_builder.py:268–280):
   lo = center - 150
   hi = center + 150
   start = floor(lo / 50) * 50
   for v in [start, start+50, start+100, ...] while v <= hi:
     type = "round_00" if v % 100 == 0 else "round_50"
     emit Level(float(v), type, "arithmetic")

E. H1 3-BAR FRACTAL SWING LEVELS (H1_SWING, H1_SWING_HIGH, H1_SWING_LOW)
   ──────────────────────────────────────────────────────────────────
   DEFINITION: H1 bars where price turned at least 2 times within 5 pips
   LOOKBACK: 10 trading days (240 hours)
   
   ALGORITHM (view_builder.py:320–360):
   1. Load 240 recent H1 bars (bars ≥ ts - 240h)
   2. Find 3-bar fractals: bar i with high[i] ≥ high[i±1] (highs) / low[i] ≤ low[i±1] (lows)
   3. Cluster raw swings within 5 pips (greedy 1-D cluster)
   4. Keep clusters with ≥2 touches; emit Level(avg_px, "h1_swing" | "h1_swing_high" | "h1_swing_low", f"h1_fractal:{len(cluster)}_touches")

F. BOLLINGER BANDS (BB_UPPER, BB_LOWER)
   ──────────────────────────────────
   SOURCE: H1 or 5m closes (last 20 bars, default BB_PERIOD=20, k=2.0 stddev)
   
   FORMULA (qm_liquidity_level_mapper.py:189–196 / significant_locations.py:315–345):
   mid = SMA(closes[-20:])
   σ = sqrt(Σ(close - mid)² / 20)
   upper = mid + 2*σ
   lower = mid - 2*σ
   
   EMITS (significant_locations.py:337–344):
   Level(upper, "BB_UPPER", "qm_liquidity_level_mapper._bollinger", source_timestamp=last_ts, timeframe="H1")
   Level(lower, "BB_LOWER", ...)


3. CLUSTERING & CONFLUENCE SCORING
───────────────────────────────────

A. TOLERANCE WINDOW
   ─────────────────
   Definition: Two levels are in the same cluster if their price distance ≤ CONFLUENCE_WINDOW_PIPS
   Default (configurable): 5.0 pips (QM_CLUSTER_WIDTH_PIPS env var; also DEFAULT_CLUSTER_WIDTH_PIPS in significant_locations.py:77)
   
   Enforcement points:
   • view_builder._cluster_zones() at :366–389 uses CONFLUENCE_WINDOW_PIPS (hardcoded 5.0 at line 60)
   • significant_locations._cluster_levels() at :455–485 uses cluster_width_pips parameter (default cw = DEFAULT_CLUSTER_WIDTH_PIPS = 5.0)
   • level_computation._cluster_candidates() at :587–621 uses LEVEL_CONFLUENCE_TOLERANCE_PIPS (hardcoded 5.0 at line 54)

B. GREEDY 1-D CLUSTERING
   ──────────────────────
   ALGORITHM (same across all modules):
   1. Sort levels by price
   2. Initialize clusters = [[level[0]]]
   3. For each subsequent level:
      - If price - last_cluster[-1].price ≤ tolerance: append to current cluster
      - Else: start new cluster
   
   IMPLEMENTATION REFS:
   • view_builder._cluster_zones() :366–389
   • significant_locations._cluster_levels() :455–485
   • level_computation._cluster_candidates() :587–621

C. CONFLUENCE SCORE COMPUTATION
   ──────────────────────────────
   Per cluster:
   • Raw confidence_count = number of distinct SOURCE CATEGORIES in the cluster
   • Example: if a cluster contains {PIVOT, PDH, ROUND_00}, confidence_count = 3
   
   IMPLEMENTATION (view_builder.py:376–388):
   for cluster in clusters:
     types = {l.type for l in cluster.levels}
     center = mean(prices)
     strength = len(cluster.levels) + len(types)  ← STRENGTH METRIC
     emit Zone(center=center, lo=min(prices), hi=max(prices), strength=strength)
   
   IMPLEMENTATION (significant_locations.py:616–620):
   for cluster:
     distinct_categories = len({source_category(member) for member in cluster})
     confluence_count = distinct_categories
   
   IMPLEMENTATION (level_computation.py:616–620):
   for cluster:
     bases = {category_base_name(member) for member in cluster}
     confluence_count = len(bases)


4. RANKING & SEPARATION ENFORCEMENT
────────────────────────────────────

A. SORTING RULE
   ──────────────
   PRIMARY: by descending confluence_count (highest confidence first)
   SECONDARY: by category priority (in case of tie)
   
   IMPLEMENTATION (level_computation.py:624–632 _rank_clusters):
   sorted(clusters, key=lambda c: (-c["confluence_count"], _CATEGORY_RANK.get(anchor_category)))

B. MINIMUM SEPARATION (15 pips)
   ────────────────────────────
   Enforce 15-pip minimum distance between any two retained levels
   
   IMPLEMENTATION (level_computation.py:635–650 _enforce_separation):
   kept = []
   for cluster in ranked:
     if any(|cluster.price - kept[i].price| < 15 for i in kept):
       skip cluster
     else:
       keep cluster
     if len(kept) >= max_count (default 6):
       break

C. FINAL LEVEL CAP
   ────────────────
   Maximum 4–6 levels (LEVELS_MIN_COUNT, LEVELS_MAX_COUNT)
   Default: 6 levels per side (resistance + support) or 4–6 total
   
   IMPLEMENTATION (level_computation.py:58–59, :639):
   LEVELS_MIN_COUNT = 4
   LEVELS_MAX_COUNT = 6
   kept = _enforce_separation(ranked, min_sep=15.0, max_count=6)

AMBIGUITIES & CLARIFICATIONS NEEDED
────────────────────────────────────

1. **Daily Pivots Authority (ig_daily_pivots vs daily_snapshot)**
   
   Current state (2026-10):
   • ig_daily_pivots.py (v2/build2 branch) is a NEW module that fetches IG REST once per day
     → Populates /opt/tradingbot/cache/htf/daily_pivots.json
     → **NOT YET WIRED INTO PRODUCTION** (still feature-flagged, spec §2)
   • daily_snapshot.py is the FALLBACK: deterministic rebuild from HTF D1 cache
     → Formula identical to ig_daily_pivots; deterministic and audit-trail-clean
   
   FOR BACKTEST RECONSTRUCTION: Use daily_snapshot.build_snapshot(symbol, trading_date)
   (no external API calls; reproducible). The ig_daily_pivots flow is for production
   live trading accuracy alignment with IG's own displayed pivots.

2. **H1 Swing Fractal Definition Ambiguity**
   
   Current: "price turned ≥2 times within 5 pips" (view_builder.py:320–360)
   
   WHAT THIS MEANS:
   • Raw swings = 3-bar fractals: high[i] ≥ high[i-1] and high[i] > high[i+1] (+ high[i-2], high[i+2])
   • Greedy cluster within 5 pips: group swings whose prices are ≤5 pips apart
   • Keep clusters with ≥2 members (the "turned ≥2 times")
   
   AMBIGUITY: "turned" = "revisited the price level (cluster) ≥2 times" not "changed direction 2x"
   → Clarify if backtest should use same fractal definition or a different swing detector.

3. **Tokyo H/L vs London AM H/L Availability**
   
   CURRENT (view_builder.py:320–360 H1 swings):
   • H1 lookback = 240 hours = 10 trading days
   • NO SPECIAL TOKYO SESSION WINDOW (unlike level_computation.py:370–380)
   
   TOKYO SESSION (22:00 prev-day → 06:00 today UTC):
   • Pre-session by the time London trading starts (07:00 UTC)
   • Data is COMPLETE before session begins

4. **"Confidence Score" vs "Strength" Metric**
   
   view_builder (current production):
   • strength = len(cluster.levels) + len(cluster.types)
   • MIXES cardinality (count of level objects) + diversity (count of level types)
   • NOT a pure "confluence count" (which would be distinct source categories only)
   
   significant_locations (Stage 5, newer):
   • confluence_count = distinct source categories
   • PURE category count
   
   level_computation (Phase 7, not yet wired):
   • confluence_count = distinct base category names
   • Explicit vocab mapping (_CATEGORY_TO_VOCAB_TAG)
   
   FOR BACKTEST: Use significant_locations.confluence_count (most semantically clear).
   view_builder.strength is a SEMI-STRENGTH metric; see view_builder.py:156 for the definition.

5. **Round-Number Grid Ambiguity**
   
   Current: 50-pip grid (1.3500, 1.3550, 1.3600, 1.3650, 1.3700, ...)
   
   MISMATCH IN NAMING:
   • view_builder calls them "round_00" (100-pip multiples) and "round_50" (50-pip offsets)
   • But the grid is a 50-pip STEP; "round_00" means the value v % 100 == 0
   • E.g., 1.3500 is "round_00", 1.3550 is "round_50", 1.3600 is "round_00"
   
   ALGORITHM (view_builder.py:268–280):
   for v in [start, start+50, start+100, ...]:
     type = "round_00" if v % 100 == 0 else "round_50"
   
   FOR BACKTEST: Same logic; explicitly: multiples of 100 = round_00, multiples of 50 = round_50.
