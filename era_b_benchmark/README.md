# Era B GBPUSD_BB_BOUNCE_S — historical benchmark

**Purpose.** A minimal, self-contained implementation of the
GBPUSD_BB_BOUNCE_S strategy as it ran during **Era B (2026-05-23 →
2026-06-24)**, pinned to the pierce + rejection-close entry and the
4-exit management (SL / scale-out+BE / broker-TP / max-hold) that the
[spec](spec_pins/gbpusd_bb_bounce_s_implementation_spec_20260929.md)
attributes to that period. **Not a trader.** IG broker submission is
not imported, not callable, and not present.

Pinned inputs are at commit **`714af5b`** of
`github.com/JohnCarrington/autobot_reports` — see
[`spec_pins/SPEC_PIN.txt`](spec_pins/SPEC_PIN.txt).

## What is implemented (source of truth: spec §2, §3, §5)

| Component | Value / behaviour | Spec citation |
|---|---|---|
| Timeframe | 5-minute GBPUSD bars | §2.1 |
| Session filter | UTC 06:00 ≤ t < 17:00, weekend-excluded | §2.1, §4 |
| BB length / std | 20 / 2.0 (population variance) | §2.2, §4 |
| Pierce setup (bar N-1) | `high ≥ bbu_prev + PIERCE_THRESH_PIPS` AND `open ≤ bbu_prev` | §2.3 |
| Pierce threshold | Default **0.5 p** (code default at commit `c85481c`; run also supports 2.0) | §2.3, config UNKNOWNS |
| Rejection candle (bar N..N+2) | `|close-open| ≥ 1.5 p` AND `close < open` (SHORT) AND `close ≤ bbu_current + 1.0 p` | §2.4 |
| Rejection window | 3 bars | §2.4 |
| Fire | market SELL at `cur.close` of rejection bar (bar N close time) | §2.5 |
| Hard SL | 20 pips (Era B effective; env override of code default 12) | §5 |
| Broker TP | 100 pips | §3.1 |
| Scale-out trigger | +10 p MFE → close 50 % | §3.2 |
| Runner BE | after scale-out, SL moves to entry | §3.3 |
| Max hold | 240 min (48 × 5m bars) | §3.7 |
| Within-bar order | ADVERSE-FIRST (SL / BE before scale / TP) | benchmark convention, §1.4 of the third-candle-break report |
| Broker submission | **NEVER**: `config.IG_SUBMISSION_ENABLED = False`, no IG module imported | — |

## What is NOT implemented — see `config.UNKNOWNS`

The following were live in Era B but their algorithms are not fully
specified in the pinned spec, or require live subsystems that this
benchmark deliberately does not import. Each is a source of
false-positive fires or non-matching exit reasons:

| Missing | Effect | Mitigation |
|---|---|---|
| Cascade-disagree gate (commit `7af663d`) | benchmark over-fires (65 FP) | flagged in `false_positives.csv` |
| `regime_filter_trending` gate (commit `1c28480`) | as above | as above |
| Counter-H1 BB-pierce-reversal build (commit `e8fc9dd`) | as above | as above |
| Per-fill position size (QM / EW multipliers) | scale-out size gate + £ conversion | benchmark uses stake 1.0; scale-out fires unconditionally |
| Tick bid/ask | executable fill precision | benchmark uses candle mid; report delta_pips column |
| Soft exits: TRAIL_STOP / QM_BAND_CLOSE_INSIDE / BRIEFING_TP*/ STRUCTURE_EXIT / BB_FLIP / BB_RANGE_TARGET / EXTERNAL_MANUAL / IG_RECONCILE / LABEL_K_OPERATOR / PRE_NEWS_CLOSE / NY_CLOSE / EXIT_PROFILE_SQUEEZE / AUTO_K_PREMISE / MANAGER_PROFIT_PROTECT / BE_HIT_IG | benchmark can't reproduce these close reasons | parity CSV flags `ledger_exit_unreproducible = True` for 33 of 36 rows |

## Current results (see `outputs/summary.json`)

- **Signal parity: 36/36 (100 %)** by rejection-bar timestamp + direction.
- **65 false positives** — benchmark fires the ledger doesn't record;
  attributable to the missing gates listed above. Listed in
  `outputs/false_positives.csv` for downstream analysis.
- **0 false negatives** — every Era B ledger fill is reproduced by
  the pierce+rejection detector.
- **Price delta**: average 0.099 p, max 2.15 p (one deal, 2026-06-19,
  broker slippage on a fast-moving bar). No signal is disqualified by
  price disagreement.
- **Exit parity: 3 / 36 ledger closes are reproducible** by the
  4-exit simulator (SL_HIT, BE_STOP_POST_SCALEOUT × 2). The remaining
  33 closes are soft exits that require live subsystems this
  benchmark does not import.
- **Benchmark realised pips (matched, all rows): 228.7** vs ledger
  395.4 → **Δ = −166.7 pips**. This is the "exit engine alpha" gap
  documented in
  [`era_b_third_candle_replay/era_b_third_candle_report_20260929.md`](../era_b_third_candle_replay/era_b_third_candle_report_20260929.md)
  §7 — the actual Era B trader captured ~180 p more than a 4-exit
  simulator can from OHLC. **Do not summarise total pnl parity as a
  strategy-quality signal.**

## Gaps blocking a DEMO forward run

Ordered by severity:

1. **Cascade-disagree / regime_filter_trending / counter-H1 gates.**
   The benchmark over-fires by 65 setups vs the ledger. A DEMO forward
   run without those gates would open ~3× more trades than the Era B
   strategy did, likely dragging pnl. Either port the gate code from
   `gbpusd_bb_bounce.py` @ commit `c85481c` (`git show c85481c`) or
   accept the higher fire rate as a distinct backtest.
2. **Soft-exit engine.** 33 of 36 Era B closes cannot be reproduced.
   For DEMO forward the four hard exits (SL / scale-out+BE / broker-TP
   / max-hold) run cleanly but will exit trades much earlier than the
   Era B trader did, reducing per-fill pnl. Consider bringing the
   trader's `trade_manager.py` (as of commit `c85481c`) or a subset of
   its tier machinery.
3. **Broker execution semantics.** Fill price uses candle mid; average
   delta 0.099 p, worst 2.15 p vs ledger. Under GBPUSD DEMO with £1/pip
   stake this is ~£0.10 per trade on average; acceptable, but log the
   real spread from IG on any live run so this can be back-checked.
4. **Position sizing.** Stake fixed at 1.0. The Era B trader used
   1.0 by default but QM/EW multipliers scaled to 2.0+ on some
   fills. Scale-out logic requires size ≥ 2.0 in the real trader
   (`trade_manager.py:3627`); the benchmark ignores this gate. For
   DEMO forward, either set `TRADE_SIZE=2.0` or implement the size
   ceiling check.
5. **Env-value gap.** `.env` values for the Era B window are
   unrecoverable (env-history archive begins 2026-09-21). Any DEMO
   forward should snapshot the current `.env` and log its SHA-256 in
   a manifest at the start of the run.
6. **No live regime engine.** `regime_engine.latest_result` is not
   consulted by this benchmark. If the DEMO forward wants full Era B
   fidelity, the H1 MACD histogram / slope inputs must be wired.
7. **Tick archive gap 2026-04-10 → present.** No tick-precise
   bid/ask backtest is possible against Era B without a fresh tick
   fetch from IG's history endpoint.

Once (1) and (2) are addressed, the benchmark can serve as a
regression baseline for BB_BOUNCE_S changes in Project Thirty. Points
(3) – (7) are hygiene items rather than blockers for a shadow / DEMO
run.
