## 9. Monitoring suggestions for the next 24 h

1. `journalctl -u ema-pullback.service -f | grep -E 'SETUP_EXPIRY|expired|intrabar_armed'` — the first time a pullback setup ages past 20 minutes without filling, a `SETUP_EXPIRY` log line will appear:
   ```
   [SETUP_EXPIRY] EMA_PULLBACK GBPUSD setup_id=XXXXXX state=ARMED age=1201.3s budget=1200s trigger_ts=...
   ```
2. `tail -f /opt/ema_pullback/state/setup_history.jsonl | grep -E '"event": "EXPIRED"'` — new terminal event in the ledger JSONL.
3. If the `SETUP_EXPIRY` log line never appears in a 24 h period, that is normal — most live setups fill or get EMA21-cancelled within minutes. The absence is not a failure; the presence of a wrongful deployment-of-no-op is what would be a failure.

The absence of any `cancel_race_filled` reason containing `filled_before_cancel_expiry` beyond a reasonable rate is also expected — it would only fire on an active `working_order` mode (not current prod mode) during a broker-side fill race.
