## 6. Dashboard module freshness — the only operational discrepancy

```
Dashboard process (observer_webserver.py):
    PID 770269
    STARTED Fri 2026-10-23 14:51:21 UTC
    ELAPSED 5-19:16:28 at report time
```

The dashboard web server is a long-running Python process started **5 days before the C2 deployment**. Python caches imported modules in `sys.modules`; `_trade_recommendation_payload` does `from scenario_recommendation import build_trade_recommendation` inside the function body but with no `importlib.reload()`. If the dashboard ever called `/observer/trade-recommendation` between 2026-10-23 14:51 and 2026-10-28 22:11:39 (file update), the pre-C2 version of `scenario_recommendation` is now pinned in its `sys.modules` cache.

Empirical probe — live `/observer/trade-recommendation` response at report time:

```json

"target": { "price": 13285.78, "provenance": "sequence_token_match='Downside Continuation to S1 (If R00 Break Holds)'" }
```

**The target provenance is `sequence_token_match=…`, not `trade_proposal.target_price=13285.78`.** C2 added the following code block (diff of `_backups/scenario_recommendation.py.pre-c2.20261028T223911Z` vs the current file):

```python
+        try:
+            structured_target = float(structured["target_price"])
+            target = {
+                **(target or {}),
+                "price": structured_target,
+                "provenance": f"trade_proposal.target_price={structured_target}",
+            }
+        except (TypeError, ValueError):
+            pass
```

The dashboard's live response is missing this override — target provenance is still the pre-C2 `sequence_token_match`. **The dashboard web server is running pre-C2 `scenario_recommendation.py`.**

### Material impact of the stale cache — today

- Entry price: **1.33000 either way** (both pre-C2 and C2 use structured entry when conditions match)
- Stop price: **1.33180 either way** (same)
- Target price: **1.32858 either way** — pre-C2 resolves via `sequence_token_match` to the "Downside Continuation to S1" sequence entry whose price is 13285.78; C2 resolves via `trade_proposal.target_price` directly. Both land on 13285.78 for today's scenario.

Material impact on today's trade outcome: **nil**. The displayed figures and the WAIT decision are both correct.

### Risk of leaving the stale cache in place

Pre-C2 code falls back to narrative extraction when structured proposal is partial. A scenario where `trade_proposal.target_price` is populated but the narrative sequence doesn't contain a matching token — or contains a matching token with a *different* price — would show divergent target on the dashboard vs the authoritative scenario row. No such scenario was observed today, but one case per day is plausible under the current reasoner.

**Recommendation:** stop + start the dashboard-only unit (`sudo systemctl restart live-market-observer-dashboard.service`) at the operator's next convenience. The sweeper, primary observer, and shadow-exec units are unaffected (they are oneshot/short-lived and already running fresh C2 code). This is a targeted, low-risk operation — dashboard-only — but is EXPLICITLY out of scope for this investigation (task § 12 restricts restarts). Operator action required.

## 8. Verdict

Corrections 1 and 2 **are operational in the sweeper and reasoner** — the authoritative producers of scenario rows and publication decisions. They are **not operational in the dashboard web-server process** which has a stale `sys.modules` cache from the pre-C2 import on 2026-10-23. A controlled dashboard-only restart is the standard fix and should be scheduled.

The reason today's WAIT display looks like the previous CAUTION-era shape is NOT a C1/C2 regression — it is caused by the two upstream validator rules (`CATEGORY_A_TRIGGER_WITH_EVENT_NAME`, `UNSUPPORTED_CONFIDENCE_PERCENT`) firing HIGH on every scenario revision for the specific linguistic reasons documented in `INVALID_FLAGS_ROOT_CAUSE.md`. Fixing those (not C1/C2) is the path to restoring the CAUTION/CONDITIONAL output stream.
