### 0b. `test_acceptance_walk_2026_08_26_0600_0800_gbpusd_s1` — ASPIRATIONAL SINCE BIRTH → **STOP for ruling**

**Diagnosis**: Sweep of every commit that touched the shadow / behaviour

`f30739d`, `aa248f1`, `2511e4c`, `fd1fd60`, `943d058`, `3bb95ed`,

(`cf584d9`).

**Root cause**: `qm_decision_shadow._sde_pick_zone` uses
`datetime.now(timezone.utc).date()` (wall-clock date) when querying
D1 pivots via `_prior_d1`, rather than the bar's own `ts.date()`. This
means the SHIPPED driver's zone picker will fetch today's D1 pivots on
every bar, regardless of when the bar itself is timestamped. During
the test replay (walking historical 2026-08-26 bars on 2026-09-07
wall-clock), the picker returns pivots that don't align with the
2026-08-26 bar geometry, no candidate is spawned, and the walk sits
at IDLE forever.

**Live impact assessment**: NONE. In live trading, wall-clock date
== bar date, so the defect is silent. It affects only replay /
back-fixture code paths. The test has been failing every day since
introduction without blocking any live behaviour.

**Ruling required**: this is neither a stale expectation (the
assertion is sensible) nor a regression (it never passed). Fixing
`_sde_pick_zone` to use `bar_ts.date()` is a **driver behaviour
change** — subtle: at UTC midnight, today's D1 may not yet be computed
whereas yesterday's D1 IS the correct source. Under the operator's
"do NOT improve the trading model" and "no geometry/template
changes" constraints, this modification is out of session scope.

**Action taken**: none in code. Reported here; left failing pending
an operator ruling on whether to (a) leave it aspirational, (b) skip
it explicitly, or (c) fix the driver defect (which would require a
separate design session because the midnight-boundary behaviour needs
consideration). **STOP** for that ruling.

## 1. Source-engine attribution + multi-source dedup

**Taxonomy frozen** (in `qm_join.py::SOURCE_ENGINE_TAXONOMY`):

| tag | meaning |
|---|---|
| `V1_FIRE_JOIN` | V1 fire or block snapshotted at `execute_trade` seam |
| `V2_VELOCITY_ONLY` | Cand transitions include `velocity_rejection` cause |
| `V2_SLOW_REJECTION` | Actionable SWEEP → REJECTING chain without velocity/continuation |
| `CONTINUATION` | s16_retest / s24_rearm / s24_reclaim in causes |
| `UNKNOWN` | None of the above (early-chain candidate) |

**Writer sites stamped**:
- `qm_join.stamp_fire` / `stamp_block` → `source_engine=V1_FIRE_JOIN`
- `qm_join.census_after_transition` (v2_only / v2_classified) →
  derived from candidate causes via `_derive_source_engine`
- `trade_executor.execute_trade` in-place fire-write path also stamps
  `source_engine` + `dedup_hint` for the direct
  `_write_join_line(_qm_join_snap)` call (this was previously
  bypassing `stamp_fire` — see Item 4 for the finding).

**Multi-source dedup** (`_check_and_emit_multi_source_link`): a
ring-buffered `_SOURCE_RING` holds recent `(sym, round(zc,1), side,
5m-bucket, source_engine)` tuples. When a new event's hint matches a
prior event within `(zc ± 2p, bucket ± 3)`, an ADDITIVE
`multi_source_link` row is written to `qm_join.jsonl` with the
combined source (e.g. `V1_FIRE_JOIN+V2_VELOCITY_ONLY`). Original rows
are never rewritten — the grader deduplicates by reading the link
rows separately.

**Grader section REPORT C** (per-source engine) added to
`scripts/qm_join_grade.py`. Sample output on 2026-09-04:


## 3. Per-refusal attribution + counterfactual (REPORT D)

Added to `scripts/qm_join_grade.py`. Every non-trade is grouped by
the layer that refused it (ENTRY_HOURS / COHERENCE / GRIND_SCRATCH /
LABEL / V2_SCORE). For each guard:

- `picks` — refusals in scope
- `GOOD / BAD / TIMEOUT` — 36-bar counterfactual outcome
- `avoided_bad` — refusals where the counterfactual entry would have
  been BAD (the guard did its job)
- `cost_good` — refusals where the counterfactual would have been
  GOOD (the guard cost us)
- `net(pips)` — approximate counterfactual net (mfe on GOOD,
  −20p SL bound on BAD, actual pnl for V2_SCORE which is on real V1
  fires)

**V2_SCORE** is a shadow guard: V1 fired anyway; the row reports what
V2 gating WOULD have delivered had it been binding on those fires.

Sample output on 2026-09-04 (after the pip-scale fix in the same
session — see caveat below):

```
guard             picks   GOOD    BAD  TIMEOUT  avoided_bad  cost_good   net(pips)
COHERENCE             3      0      2        1            2          0       -40.0
ENTRY_HOURS           1      0      0        1            0          0        +0.0
V2_SCORE              6      3      3        0            3          3       +75.4
GRIND_SCRATCH         0      0      0        0            0          0        +0.0
LABEL                 0      0      0        0            0          0        +0.0
```

**Reads**: COHERENCE did its job twice on 09-04 (avoided-bad). V2 as
a would-be gate would have refused 3 of 6 GOOD V1 fires (mixed —
cost-good).

**Instrument caveat (SAME SESSION)**: the grader's
`simulate_hypothetical` was multiplying pip deltas by 10 000× because
`PIP_SIZE[pair]` was set to the real-price pip size (1e-4) whereas
the candle files store price × 1e4 (so 1 file-unit already IS 1 pip).
This produced garbage MFE/MAE numbers (e.g. `mfe_pips=21000` for a
2-pip favourable move). Fixed by setting `PIP_SIZE[pair] = 1.0` for
every pair. This IS a measurement fix, not a threshold change — the
sim now reports honest 36-bar counterfactuals. Reported here for
transparency; the outcome tables above are the post-fix numbers.

## 5. Executor boundary — dark-wired

New module `qm_v2_executor.py`. Two entry points:

- `build_intent(cand)` — constructs a `StrategyDecision` from an
  ENTRY_ARMED candidate. Entry from `cand.hypothetical_entry`; SL/TP
  from `QM_V2_LIVE_SL_PIPS` (20) / `QM_V2_LIVE_TP_PIPS` (30); mode
  string `QM_V2_{ENGINE}_{L|S}` where ENGINE ∈ {VELOCITY,
  SLOW_REJECTION, CONTINUATION}; direction from rejection geometry
  (mirrors `qm_pick_alerts._direction_for` precedence).

- `maybe_fire_from_candidate(cand)` — gated by
  `QM_LIVE_FIRE` (default `0`, and **absent from `.env`** — doubly
  dark). When ON, builds the intent and dispatches via
  `trade_executor.execute_trade(intent, epic)` — the SAME seam as V1
  fires, so ENTRY_HOURS / COHERENCE / GRIND_SCRATCH / news-window
  guards apply automatically. When OFF, returns None without ever
  importing or touching `execute_trade`.

**Tests** (`tests/unit/test_qm_v2_executor.py`, 10 pass):

- intent correctness — velocity BUY, slow-rejection SELL, env
  overrides, mode string, direction from geometry;
- **zero order calls when flag absent** — `execute_trade` is
  monkey-patched to raise; `maybe_fire_from_candidate` still returns
  None cleanly;
- **zero order calls when flag=0** — same;
- **flag-on smoke against mock executor** — `execute_trade` records
  the call and returns a stub; the intent reaches it with the
  correct fields;
- rejects non-armed states even when flag is on.

**No caller is wired to `maybe_fire_from_candidate` in this build.**
