## 10. Monitoring suggestions for the next 24h

Watch for the following journal patterns:

```
$ journalctl -u ema-pullback.service -f | grep -E 'watch_state|WATCH_STATE_CANCEL'
```

* `"kind": "watch_state_pass"` — authority allowed the admission. Fields include `state`, `evaluation_ts`, `age_seconds`, `last_bar_age_seconds`.
* `"kind": "watch_state_blocked"` — admission refused. If `binding=watch_state_block`, the authority is in WATCH_AND_WAIT or REVERSAL_CONFIRMED. If `binding=snapshot_fail_closed`, the snapshot is missing / stale / malformed — escalate.
* `[WATCH_STATE_CANCEL] EMA_PULLBACK GBPUSD setup_id=XXXXXX state=ARMED ...` — an ARMED setup was cancelled because W&W entered post-arm. Expected during trend exhaustion windows.
* `cancel_race_filled` with `reason` containing `watch_state` — the broker FILLED a working order between our verdict and our cancel. Rare, non-fatal, promoted to IN_TRADE.

`setup_history.jsonl` event types to grep for:
* `WATCH_STATE_BLOCKED` — audit-only SKIPPED Setup recording each block.
* `CANCELLED` with `cancellation_reason` starting `nms_watch_and_wait_block:` — step-level cancellations of pending setups.

If the first 24 hours produce no `watch_state_pass` lines, it means EMA PB has not armed any setup in that window — not a failure. The gate is only consulted at admission attempts.
